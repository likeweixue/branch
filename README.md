## 这是什么

宗谱（ZUPÚ）是用来**记录一支家族血脉**的轻量系统。它把每个人画成谱系图上的一个节点：父子/母子用浅色线相连，两姓结姻用红线相连，整个谱系像文件夹的分支一样一层层展开。

和常见的族谱程序不同，它**不需要 MySQL**——所有数据保存在 `data/` 下的三个 JSON 文件里，思路类似 DokuWiki：拷走目录就是完整备份，丢到任何一台装了 PHP 8 的机器上就能跑。

适合的场景：

- 一个小家族自己维护一份电子族谱；
- 想给长辈看看"这个人该叫啥"，不想翻纸质谱；
- 想在手机上打开就能看，不需要装 App；
- 不想为了一个族谱去维护数据库和运维。

**它现在有什么：**

- 🌳 **树杈式谱系图** —— SVG 绘制，可平移、缩放、一键适配；横排/竖排随时切换
- 🖱️ **悬停即知** —— 鼠标停在头像上，显示姓名、生卒、字辈，以及"我该叫他什么"
- ✍️ **画布编辑器** —— 像 macOS 无边记那样自由拖节点、拉线建关系，布局会保存到前台
- 🔤 **字辈体系** —— 自定义字辈序列，自动识别长幼与排列方向
- 🎬 **启动动画** —— 仿 DeepSeek 启动页的视觉语言，首次访问播放，可关
- 🖼️ **成员头像** —— 贴图床直链即可，谱系节点、悬浮卡、语录卡片统一显示
- 📷 **家族相册** —— 错位照片墙，滚轮缩放、拖拽平移、点击放大；按年代筛选
- 📝 **续谱收集表** —— 亲戚填表提「新增/修正」，管理员审核后才并进族谱（像一次 PR）
- 👥 **账号与权限** —— 管理员建用户、绑定成员；访客可注册
- 💾 **零数据库** —— 纯 JSON 文件存储，原子写入，拷目录即备份

## 快速开始

### 环境要求

- **PHP 8.0 或更高**（用到 `password_hash`、`str_contains` 等 8.x 特性）
- 需要写权限：`data/` 目录（首次访问自动创建）
- 不需要：MySQL、Redis、Composer、Node.js、任何构建步骤
- 依赖扩展：`json`、`session`（PHP 默认自带）

### 方式 A：双击启动（macOS，零安装）

仓库根目录双击 **`start.command`** 即可。首次运行会自动下载一个免安装的静态 PHP（约 30 MB，放在 `.runtime/`，已被 git 忽略），之后每次都是秒开。

- 自动挑选空闲端口（8080 起），并打开浏览器；
- 终端窗口保持打开即服务运行，按 `Ctrl+C` 或关窗口即停止；
- 首次打开若提示"无法验证开发者"，右键点 `start.command` → 打开，或执行：

```bash
xattr -d com.apple.quarantine start.command
chmod +x start.command
```

### 方式 B：已有 PHP 环境

```bash
git clone git@github.com:likeweixue/branch.git zupu
cd zupu
php -S 127.0.0.1:8080 -t . router.php
```

浏览器打开 <http://127.0.0.1:8080/>。首次访问会自动写入示例家族与默认账号。

> `router.php` 是本地预览用的路由脚本，会拦掉对 `/data/` 的直接访问（返回 403），与生产 nginx 的行为一致。
>
> ⚠️ PHP 内置服务器是单进程、无并发的，**只适合本机自测**。对外提供服务请用下面的 nginx 配置。

### Nginx 部署

仓库自带 [`nginx.example.conf`](nginx.example.conf)，改三处即可：

```nginx
server {
    listen 80;
    server_name 你的域名;
    root /var/www/zupu;          # ① 指向仓库根目录
    index index.php;

    location ^~ /data/ {         # ② 关键：数据目录禁止外网访问
        deny all;
        return 403;
    }

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;   # ③ 按实际 php-fpm sock 改
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
```

目录权限建议：

```bash
chown -R www-data:www-data /var/www/zupu
find /var/www/zupu -type d -exec chmod 755 {} \;
find /var/www/zupu -type f -exec chmod 644 {} \;
```

`data/` 由 PHP 自动创建；若手工创建，确保运行用户（如 `www-data`）可写。

## 数据存储

七个文件，全部是可直接阅读的 UTF-8 JSON：

| 文件 | 内容 | 是否入库 |
| --- | --- | --- |
| `data/members.json` | 家族成员数组 | ✅ 随仓库提供 |
| `data/quotes.json` | 家族语录数组（长辈原话与嘱托） | ✅ 随仓库提供 |
| `data/events.json` | 家族大事记数组（时间线） | ✅ 随仓库提供 |
| `data/photos.json` | 家族相册数组（**只存链接**：站内 `photos/` 或图床，不存图片本身） | ✅ 随仓库提供 |
| `data/submissions.json` | 续谱提交（待审 + 已处理留档，含提交人联系方式） | ❌ 不入库（运行时生成） |
| `data/users.json` | 账号数组（密码为 `password_hash` 哈希，非明文） | ❌ 含凭证，首次运行自动生成 |
| `data/settings.json` | 字辈序列、排列方向、连线颜色、启动页配置 | ✅ 随仓库提供 |

> ⚠️ 本仓库的 `data/members.json`、`quotes.json`、`events.json` 与 `core/seed.php` 是同一套家族内容。若不想这些内容留在公开仓库，需要**同时**替换数据文件与 `seed.php`——只删 `data/` 的话，下次访问会按 `seed.php` 重新播回同一套数据。

**写入是原子的**：先写 `xxx.json.tmp`（`LOCK_EX` 加锁），再 `rename()` 覆盖正式文件，避免并发写入把 JSON 写坏。

### 成员字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 自增 ID，如 `m13` |
| `name` | string | 姓名 |
| `zi_bei` | string | 字辈用字，如 `永`；娶/嫁入者可留空 |
| `gender` | string | `male` / `female` |
| `birth` / `death` | string\|null | `YYYY-MM-DD`，健在时 `death` 为 `null` |
| `bio` | string | 简介、生平 |
| `avatar` | string | 头像地址（图床直链，可空；空则显示姓名首字） |
| `father_id` / `mother_id` | string\|null | 指向父母成员的 `id` |
| `spouse_ids` | string[] | 配偶 ID 数组，服务端强制双向互惠 |
| `order` | number | 同辈排行，数字越小越年长 |
| `pos` | object\|null | 画布编辑器保存的坐标 `{x, y}`（节点中心，世界坐标；`layout_mode = custom` 时生效） |

### 语录字段（`quotes.json`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 自增 ID，如 `q1` |
| `member_id` | string\|null | 讲述人（指向成员）；为空时用 `speaker` 手填姓名 |
| `speaker` | string | 未绑定成员时的姓名，如「麻家爷爷」 |
| `relation` | string | 称谓 / 身份，如「祖父」「父亲」 |
| `text` | string | 语录正文（原话） |
| `context` | string | 场合 / 背景，如「年节家宴上的嘱托」 |
| `year` | string | 年份或年代，可空（自由文本，如 `1998`、`1990 年代`） |
| `created` | string | 录入时间 |

### 大事记字段（`events.json`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 自增 ID，如 `e1` |
| `date` | string | 年代 / 日期，自由文本（`1949`、`1985-03`、`1980 年代`），可空=待考 |
| `title` | string | 事件标题 |
| `text` | string | 经过 / 说明 |
| `category` | string | 分类：迁徙 / 婚嫁 / 添丁 / 求学 / 事业 / 家谱 / 其他（也可自填） |
| `member_ids` | string[] | 关联成员 ID |
| `created` | string | 录入时间 |

> 时间线按 `date` 里的 4 位年份正序排列，没有年份的条目排在最后并显示「待考」。

### 相册字段（`photos.json`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 自增 ID，如 `p1` |
| `url` | string | **图片地址**：站内相对路径（如 `photos/01-xxx.jpg`）或图床直链 |
| `title` | string | 标题，如「1985 年春节全家福」 |
| `date` | string | 拍摄时间，自由文本（`1985`、`1985-02`），可空；4 位年份用于筛选 |
| `place` | string | 地点 |
| `note` | string | 说明 / 背后的故事（灯箱里显示） |
| `member_ids` | string[] | 照片里的人（灯箱中显示姓名） |
| `created` | string | 录入时间 |

> 两种放法都支持：① 照片放进仓库的 `photos/` 目录，随站点一起发布，最省事；② 贴图床直链，站点不占空间。
>
> 用图床时**链接失效照片就会挂**（前台会显示「图片加载失败」占位，不会白屏）；放站内则不受外部服务影响。

## 使用指南

### 1. 录入成员与设置字辈

进入 **后台 → 成员管理**：

- 姓名必填；字辈可手输，也可从下拉（datalist）里选；
- 父亲/母亲各填其一即可，都填则双系都在谱系上；
- 配偶可多选，保存后自动双向建立姻亲关系；
- 排行用于同辈排序（兄弟长幼）。

**字辈与排列**标签页里编辑字辈序列，用空格或逗号分隔，例如：

```
仁 德 朝 众 大 从 先 正 子 文 国 安 常 孟 学 永 远 照 光 明
```

### 2. 排列方向

## 亲属称呼是怎么算的

不查表、不预存，纯按谱系图实时推导：

1. **取双亲**：沿 `father_id` / `mother_id` 建立"我"的双亲集合；
2. **求祖先与代数**：从双亲 BFS 上溯，得到每个祖先到"我"的代数距离（父系/母系分别记录）；
3. **判直系**：目标在我祖先集中 → 按代数与父/母系给称呼（祖父 vs 外祖父）；
4. **判晚辈**：我在目标祖先集中 → 按代数给子/女、孙/孙女、曾孙……；
5. **判旁系**：都不是，则求**最近共同祖先（LCA）**，用"上几代 + 下几代"定位，再结合性别与长幼给称呼。

支持的称呼（节选）：

| 关系 | 称呼 |
| --- | --- |
| 父 / 母 | 爸爸 / 妈妈 |
| 父之父 / 父之母 | 祖父 / 祖母 |
| 母之父 / 母之母 | 外祖父 / 外祖母 |
| 父之兄 / 父之弟 / 父之姐妹 | 伯父 / 叔父 / 姑母 |
| 母之兄弟 / 母之姐妹 | 舅父 / 姨母 |
| 同辈 | 兄 / 弟 / 姐 / 妹 |
| 下一代 | 子 / 女 / 侄 / 侄女 / 外甥 / 外甥女 |
| 再下一代 | 孙 / 孙女 / 侄孙…… |
| 旁系同辈 | 堂兄/堂弟/堂姐/堂妹、表兄/表弟/表姐/表妹 |

**已知边界**：只处理"血缘 + 一层姻亲"；多婚、过继、跨谱联姻、辈分错乱等极端情形会退化为笼统称呼。这部分算法附有 14 例单元测试（父系/母系/旁系长幼/侄甥性别等），目前全部通过。

## 常见问题

**Q：后台打开是一片空白 / 没有表格？**
v0.0.2 起成员表、用户表、各下拉框都由 PHP 服务端渲染，JS 挂了也应能看到数据。如果你仍看到空白，依次检查：① 是否已把新版 `admin.php` 覆盖到服务器；② 浏览器强刷（`Cmd/Ctrl + Shift + R`）清缓存；③ PHP 是否有报错（看 nginx/php-fpm 错误日志）；④ `data/*.json` 是否为空或损坏。

**Q：启动页只出现一次，怎么再看？**
在地址后面加 `?splash=1` 可强制重播（如 `http://127.0.0.1:8080/?splash=1`）。也可以改用无痕窗口、把后台"播放时机"改为"每次访问"，或清掉浏览器 localStorage 里的 `zp_splash_seen`。

**Q：双击 `start.command` 提示"无法打开，因为无法验证开发者"？**
右键点它 → 选「打开」→ 再点「打开」即可（macOS 的一次性放行）。或直接执行：

```bash
xattr -d com.apple.quarantine start.command
chmod +x start.command
```

**Q：提示端口被占用？**
`start.command` 会自动从 8080 往后找空端口，并在终端里打印实际地址。若 8080-8100 全被占，先关掉占用的程序（`lsof -nP -iTCP:8080 -sTCP:LISTEN` 可查）。

**Q：忘记管理员密码了？**
生成一个新哈希，替换 `data/users.json` 里对应用户的 `password` 字段：

```bash
php -r "echo password_hash('你的新密码', PASSWORD_DEFAULT), PHP_EOL;"
```

**Q：怎么把示例家族换成我自己的？**
后台逐条编辑/删除即可。若还没录真实数据，直接 `rm data/*.json` 重置更省事。注意重置会连账号一起清空，回到 `admin/admin123`。

**Q：为什么不用 MySQL？**
族谱是**读多写少、数据量小、结构简单**的典型场景，一个家族通常几十到几千人，JSON 完全够用。换来的是：不用装数据库、不用写迁移、拷目录即备份、任何虚拟主机都能跑。真到了多家族、高并发的规模，再换存储也不迟。

**Q：中文会不会乱码？**
所有文件按 UTF-8 处理，JSON 以 `JSON_UNESCAPED_UNICODE` 输出。请确保编辑器保存为 UTF-8 无 BOM。

**Q：能多人同时编辑吗？**
可以，但 JSON 是整文件写入——两人同时保存时，后保存的会覆盖先保存的。多人协作场景建议约定"一人主编辑"。

## 安全建议

1. **改掉默认密码**（`admin` / `zhang`），并删除不用的账号；
2. **务必配置 `location ^~ /data/ { deny all; }`**，否则谱系与账号哈希可被直接下载；
3. 正式对外请上 **HTTPS**（会话 Cookie 会自动带 `secure` 标记）；
4. `data/` 目录权限收紧到运行用户可写、其他用户不可读；
5. **定期备份** `data/`，它是全部家当；
6. 本系统无上传功能、无 SQL、无第三方依赖，攻击面主要就是"数据目录暴露"和"弱密码"这两点。

## 续谱收集表

族谱最容易死在「只有一个人能改，别人想补也无从下手」。所以这里做了一张**免登录的收集表**：亲戚打开 `submit.php` 就能填，提交进队列，管理员点头才落到族谱上——本质是一次 PR：**提交 → 审核 → 合并**。

### 谁能提交

任何人，不用账号。所以表单做了基本防护：字段长度上限、图片链接白名单（`zp_clean_url()` 拒绝 `javascript:` 之类）、隐藏蜜罐字段，以及同一个人 10 分钟内重复提交同一份内容只记一条。

### 表单里能填什么

| 分区 | 字段 |
| --- | --- |
| 类型 | 新增一位家人 / 修正现有信息（后者选中人会自动带出既有资料） |
| 本人 | 姓名、字辈、性别、出生、逝世、头像链接、简介 |
| 亲属 | 父亲、母亲（从现有成员里选）、配偶（可多选，最多 4 位） |
| 提交人 | 称呼、联系方式（微信/电话）、说明（依据：谁口述、族谱第几页、墓碑照片…） |

提交成功会拿到一个受理编号（`#s3`），并明确告知「不会立刻出现在族谱上」。

### 管理员怎么审

后台 → **续谱审核**（标签上带待审条数角标）：

- **新增**：完整列出将写入的每个字段值；
- **修正**：只列**有差异**的字段，左「现在」右「提交」，一眼看出改了什么；
- 点 **批准并合并** → 立刻写进 `data/members.json`（配偶关系自动双向补齐；新成员按兄弟姐妹数量排好同辈次序）；
- 点 **驳回** → 状态转 `rejected` 留档，附驳回原因，记录不删除；
- 已处理的提交在下方「已处理」表格里可回溯。

> 合并新成员时会清掉画布上的手工坐标（`pos`），下次打开族谱按自动布局重排——否则新旧坐标混在一起会重叠。

### 数据结构

`data/submissions.json`（不入库，属运行时数据）：

| 字段 | 说明 |
| --- | --- |
| `id` | `s1`、`s2`… |
| `type` | `new` 新增 / `edit` 修正 |
| `status` | `pending` / `approved` / `rejected` |
| `target_id` | 修正时的目标成员 id |
| `payload` | 待写入的成员字段（修正模式只含真正提交的字段） |
| `submitter` | `{name, contact}` 提交人 |
| `note` | 说明 / 依据 |
| `submitted` / `ip` / `reviewed` | 时间、来源、审核记录（`{by, at, note}`） |

## 土地与坟茔

两个和「地方」有关的模块，都在后台录入、前台展示，共用一套零依赖地图。

### 土地（`land.php`）

一块地一张卡：面积、位置、状态、现归谁、照片，以及**流转史**——哪一年、因为什么、分给了谁。

| 字段 | 说明 |
| --- | --- |
| `name` / `area` / `unit` | 地块名、面积、单位（亩 / 分 / 平方米） |
| `location` | 小地名，如「村东头水井旁」 |
| `lat` / `lng` | 经纬度，留空则不上地图 |
| `status` | 在册 / 已分 / 已卖 / 已征 / 撂荒 / 其他 |
| `owner_ids` | 现归属成员 id 数组 |
| `history[]` | `{date, event, to_ids, note}`——时间、事由、分给了谁（可多人）、补充说明 |
| `photos[]` | 图床直链或站内 `uploads/…` |

首页统计会自动合计「亩」为单位的面积；不同单位混填时只作数量统计，不做换算。

### 坟茔（`grave.php`）

| 字段 | 说明 |
| --- | --- |
| `name` | 墓名；留空时按第一位安葬人自动生成「某某墓」 |
| `member_ids` | 安葬的家人，合葬可多选 |
| `place` / `address` | 小地名 + 怎么走的详细说明 |
| `lat` / `lng` | 经纬度 |
| `facing` / `type` | 朝向（坐北朝南）、形制（土坟 / 石墓 / 合葬 / 骨灰 / 衣冠冢） |
| `date` / `visited` | 立碑或下葬时间、最近一次祭扫 |
| `photos[]` | 墓碑与周边照片 |

### 星空是怎么算亮的

没登录时每颗星一样亮；登录后按**亲属跳数**（父/母/配偶/子女都算一条边）给分：

```
亮度 = 1 / (1 + 0.5 × (跳数 - 1))     最低 0.34
直系血脉（祖→己 或 己→后代）额外 +0.14
无亲属路径 0.22
```

所以父母/子女最亮，祖辈兄弟暗一档，旁系与无亲缘更暗——星越多，说明家里走过的人越多。

> 坟茔页若要显示「与你的距离」，需要账号在后台绑定了对应成员（用户管理 → 绑定成员）。

### 地图底图

`assets/js/zmap.js` 是自己写的小地图，不依赖 Leaflet。

底图三选一（地图右下角切换，会记住上次选择）：

| 底图 | 说明 |
| --- | --- |
| **素白**（默认） | 在线瓦片，但整层降饱和：白陆地、浅灰水面、细线条、淡灰字，接近 Positron / Radiocast 那类纸质地图。既有真实路网地名，又不花 |
| **高德** | 原色瓦片，信息最全，但色块偏多；坐标为 GCJ-02，与 WGS-84 标点有几百米偏移 |
| **离线** | **完全离线**。Canvas 按 Web Mercator 自绘经纬网、度数刻度、比例尺、指北针与柔和地形晕染，不发任何网络请求，**永远不会 404** |

### 地球视图

缩到 **3 级及以下**，地图会自动变成一颗地球：正交投影、浅灰海面、白陆地、极淡经纬网、左上来光、右下压暗，外加一圈轮廓边和球下柔影；深色主题下是「夜半球」。地图控件里的 `◒` 可以一键跳过去。

- 陆地轮廓来自 `assets/data/world-land.js`（Natural Earth 110m，Douglas-Peucker 0.3° 抽稀，24 KB，纯静态零请求）。
- 跨地平线的陆地在 3D 里用 `z=0` 平面做一次裁剪，再把落在轮廓线上的相邻点沿圆弧补密，所以不会有「白色楔形」或直线切口。
- 地名只放 20 个左右（北京、上海、广州、成都、东京……），球太小（半径 < 150px）就整层不标。
- 这一级不发瓦片请求，标点会收成带白边的小红点。

在线瓦片连续失败会自动**静默退回离线底图**并给出提示，不会留一片空白。

> 为什么不做「下载离线瓦片」？一个县 z10–z14 要几万张图、上百 MB，塞进仓库不现实，且 OSM/高德瓦片都有使用条款。自己按投影画底图，体积不到 20KB，效果够用且永不失效。

浅色主题给土地页用（宣纸色），深色主题给坟茔页用（星夜色），由 `new ZMap(el, { theme: 'light'|'dark' })` 指定。

### 土地页的两个视图

默认只显示地块卡片，点「地图」才铺开地图——不想让一张地图常驻挤占阅读宽度。

- 宽屏下地块卡片两列排布；
- 点地图上的地块名，左下角弹出信息卡（面积、位置、现归、最近一次流转），可跳回完整流转；
- 卡片上的「定位 ↗」会自动切到地图并放大到该地块；
- `land.php?view=map` 可直链到地图视图，`grave.php?view=map` 同理。

### 星空全屏

坟茔页点「星空」直接**铺满整个浏览器**，右上角「✕ 退出星空」或按 `ESC` 退出。全屏时亮度图例搬进画面左上角，星点半径、星尘密度按画布大小等比放大；在名册里点任意一张卡也会进全屏并点亮对应的星。


### 上传

后台上传的图片存在 `uploads/YYYYMM/` 下，随机文件名，仅接受 jpg / png / webp / gif / avif，单张 ≤ 6MB。该目录不入库，部署时确保 PHP 对其有写权限：

```bash
chmod -R 755 uploads
```

若用 nginx，记得给上传目录单独的 `client_max_body_size`（默认 1M 会挡掉手机原图）。

## 发版与 Release

本项目**每次打标签都会在 GitHub 同步发布一条 Release**，正文取自 [`CHANGELOG.md`](CHANGELOG.md) 对应版本的小节——这样别人点开 Releases 就能看清每个版本改了什么，不用翻提交记录。

### 一次完整发版

```bash
# 1. 写日志（新增 / 优化 / 修复三段），版本号 +1
vim CHANGELOG.md

# 2. 提交、打标签、推送
git add -A && git commit -m "feat: ..."
git tag v0.0.7
git push origin main --tags

# 3. 发布 Release（正文自动取 CHANGELOG 的 [0.0.7] 小节）
./scripts/release.sh v0.0.7
```

脚本会先检查标签是否已推到远端，已存在同名 Release 则**更新**（不会重复创建）。

**认证**：优先复用已登录的 `gh`（`gh auth login` 一次即可，令牌存在系统钥匙串里），本机 `gh auth status` 正常就不用再管令牌；没有 gh 时才退回读 `GITHUB_TOKEN` 环境变量。

Release 标题形如 `v0.0.7 · 相册真实照片，照片墙铺满一屏`——一句话主题在脚本的 `release_title()` 里按版本登记，最新版自动打 `Latest` 标。

> `gh` 不在 PATH 里也能用：脚本会自动找 `~/bin/gh`、`/opt/homebrew/bin/gh`、`/usr/local/bin/gh`；也可以用 `ZUPU_GH=/path/to/gh` 显式指定。

### 常用参数

| 命令 | 作用 |
| --- | --- |
| `./scripts/release.sh v0.0.7` | 创建（或更新）该版本的 Release |
| `./scripts/release.sh v0.0.7 --dry` | 只打印将要发布的正文，不调用 API |
| `./scripts/release.sh --all` | 按 CHANGELOG 顺序补齐**所有**版本（用于回填历史标签） |

> 仓库地址可用 `ZUPU_REPO=owner/name` 覆盖。

### 版本号约定

- `0.0.x`：功能迭代，每次 +1；
- 破坏性改动或数据结构变更，在 CHANGELOG 里单列「⚠️ 升级注意」；
- 标签统一 `v` 前缀（`v0.0.6`），Release 标题为「`v0.0.6 · 一句话主题`」。
